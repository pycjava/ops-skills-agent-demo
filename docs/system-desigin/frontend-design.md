# Frontend 模块设计说明

## 1. 模块职责

前端负责把后端的多 Agent 能力封装成统一工作台，核心职责包括：

- 提供聊天与流式输出界面
- 承载任务抽屉、提醒中心、Skills 面板、记忆面板、MCP 面板
- 维护会话、消息、附件、任务、认证等跨组件共享状态
- 同时处理 REST 请求与 WebSocket 事件流

## 2. 目录结构

```text
frontend/src/
├── App.vue                  # 主工作台
├── RootApp.vue              # 根组件
├── router.ts                # 路由与登录守卫
├── stores/
│   ├── chat.ts              # 顶层 Pinia Store 聚合
│   └── chat/                # 按领域拆分的状态域
├── components/              # UI 组件
├── composables/             # 组合式逻辑
├── views/                   # 页面级组件
├── utils/                   # 辅助函数
└── constants/               # 常量定义
```

## 3. 页面与路由设计

路由层只有两类页面：

- `/login`：登录页
- 其他路径：统一落到工作台页面

`router.ts` 在进入页面前会先调用 `fetchAuthStatus()`，根据认证开关与登录状态做跳转。这样可以保证：

- 认证开启时，未登录用户只能访问登录页
- 认证关闭时，系统直接进入工作台
- 登录成功后可以安全返回原始路径

## 4. 状态管理设计

### 4.1 顶层 Store 聚合

`stores/chat.ts` 是前端的状态中枢，负责：

- 定义共享的 `ref` / `computed`
- 创建各领域 domain
- 组合成统一的对外动作接口

它不是把所有逻辑都写在一个文件里，而是作为“状态协调器”调度多个子域。

### 4.2 领域拆分

`stores/chat/` 下按职责拆分为多个 domain：

- `conversations.ts`：会话、消息、当前会话切换
- `socket.ts`：WebSocket 生命周期与事件消费
- `attachments.ts`：附件上传、删除与会话绑定
- `tasks.ts`：定时任务列表、草稿、执行记录
- `notifications.ts`：任务提醒与未读数
- `memory.ts`：记忆树、文档内容、删除动作
- `mcp.ts`：MCP 配置与服务测试
- `auth.ts`：认证状态、用户信息、登录方式
- `helpers.ts`：通用工具函数和默认 Agent 选择逻辑

这种拆分方式兼顾了：

- 单域逻辑集中
- 顶层 Store 易于组合
- 组件调用接口保持统一

## 5. 对话交互设计

### 5.1 REST + WebSocket 双通道

前端与后端的交互分为两类：

- **REST**：用于列表查询、创建/删除、配置保存、任务管理等显式请求
- **WebSocket**：用于主会话消息流、工具事件和流式回放

### 5.2 事件驱动消息渲染

`socket.ts` 会把后端事件映射为前端消息对象。典型事件包括：

- `text_delta`：持续拼接助手输出
- `thinking_delta`：展示推理过程
- `tool_call`：插入工具调用卡片
- `routing`：提示正在路由到子 Agent
- `tool_result`：写入工具结果并识别报告/记忆产物
- `done`：结束本次流式生成
- `error`：补充错误消息并终止 loading

前端因此不是简单展示“一条消息”，而是在渲染一条消息生命周期。

## 6. 组件设计

### 6.1 工作台主体

`App.vue` 承担主工作台布局，组织以下主要区域：

- 会话列表
- 消息区
- 输入区
- Skills 面板
- 任务抽屉
- 提醒中心
- MCP 面板
- 记忆面板

### 6.2 关键组件

- `ConversationList.vue`：会话切换与标题展示
- `MessageBubble.vue`：消息、工具调用、工具结果和下载动作渲染
- `ConversationAttachmentBar.vue`：附件展示与删除
- `TaskDrawer.vue`：任务草稿、任务编辑、执行记录展示
- `TaskNotificationCenter.vue`：任务通知面板
- `McpPanel.vue`：MCP 配置可视化与测试
- `MemoryPanel.vue`：记忆树浏览与文档操作
- `SkillPanel.vue`：当前 Agent 的 Skills 展示

## 7. 用户体验设计

- **对话连续性**：消息流和工具流在同一时间线上展示，降低用户理解成本
- **Agent 可见性**：子 Agent 路由过程会显式展示，避免“黑盒切换”
- **下载闭环**：报告类产物在消息区直接暴露下载入口
- **后台任务可追踪**：任务抽屉与提醒中心共同承载异步执行反馈
- **配置可运维**：MCP 与记忆能力不藏在后端，而是提供专门面板管理

## 8. 设计取舍

- 使用单一顶层 Store 聚合多 domain，降低跨组件通信复杂度，但要求严格的模块边界
- 通过 WebSocket 直接驱动 UI，实时性好，但断线重连和中间态处理更复杂
- 工作台集成多个面板，提升一体化体验，但页面复杂度较高，需要靠组件拆分控制维护成本

## 9. 后续演进方向

- 把工作台进一步拆分为更明确的侧边栏/内容区布局模块
- 为任务回放、报告预览、附件管理引入更强的局部状态缓存
- 增强断线恢复、历史消息懒加载和长对话性能优化
