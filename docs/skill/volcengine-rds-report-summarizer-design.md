# Volcengine RDS 巡检报告汇总 Skill 设计说明

## 1. Skill 定位

`volcengine-rds-report-summarizer` 用于对多份单实例巡检 Markdown 报告做二次汇总，输出跨实例风险概览、共性问题与管理摘要。

它的输入是**已有报告**，不是云 API，也不是数据库连接。

## 2. 设计目标

- 在不重新采集数据的情况下，对多个实例做管理视角汇总。
- 保证只汇总有效、结构正确的单实例巡检报告。
- 通过固定模板生成稳定的跨实例报告。

## 3. 输入边界

Skill 要求用户提供：

- 目录范围，或
- 明确的文件列表

不允许默认扫描整个仓库。这样设计是为了控制分析范围，避免把无关 Markdown 纳入统计。

## 4. 标准执行流程

```text
获取目录或文件范围
  -> glob 枚举候选 Markdown
  -> read_file 校验每份报告是否有效
  -> 抽取单报告关键信息
  -> 做实例去重与排序
  -> 汇总风险分布和共性问题
  -> 按模板生成管理摘要
```

## 5. 报告有效性校验

该 Skill 只纳入由 `volcengine-rds-health-analyzer` 生成的单实例报告，校验重点包括：

- 标题和章节结构
- 健康评分字段
- 巡检报告生成时间等尾部信息
- 是否明显属于汇总报告而非单实例报告

设计原因：

- 防止把用户手写笔记或旧汇总文件误当成输入。
- 保证提取字段的结构稳定。

## 6. 单报告提取策略

每份报告至少提取：

- `instance_id`
- `instance_name`
- `report_time`
- `health_score`
- `health_rating`
- `health_summary`
- 主窗口 / 最近 `3d` / 最近 `24h` 标签
- 关键风险与建议

提取优先基于模板固定位置，而不是靠全文自由猜测。

## 7. 去重与排序策略

如果同一实例存在多份候选报告：

- 同一语义窗口只保留最新报告
- 旧报告归入“未纳入统计”

排序时优先考虑：

- 风险等级
- 健康评分
- 高优先级异常数量

这样可以保证输出顺序稳定，便于横向比较。

## 8. 共性问题归纳

Skill 优先归纳以下跨实例重复模式：

- CPU 持续偏高或波动明显
- 内存压力偏高
- 磁盘使用率高
- 复制延迟异常
- QPS / TPS 波动
- IOPS 或网络负载异常
- 最近新发问题
- 历史已缓解但仍需观察的问题

重点是跨实例模式，而不是逐条重写每份单实例报告。

## 9. 模板与落盘策略

该 Skill 依赖：

- `backend/skills/volcengine-rds-report-summarizer/assets/summary_report_template.md`

汇总类请求在获得可分析范围后，默认会生成 Markdown，并写入：

- `/memories/reports/皮氏咖啡线上MySQL巡检报告<YYYYMMDD>.md`

这里的关键设计是“固定命名 + 固定模板”，以保证交付物稳定且可被前端识别。

## 10. 安全与工具边界

- 不调用云 API
- 不调用数据库
- 不重跑 `volcengine-rds-health-analyzer`
- 只使用文件枚举、读取和 Markdown 写入能力

该 Skill 本质上是**离线报告分析器**，而不是在线巡检执行器。

## 11. 与其他 Skill 的边界

- 若用户只有单个实例并要重新采集，应使用 `volcengine-rds-health-analyzer`。
- 若用户只是要改 Markdown 排版，不属于该 Skill 主职责。
- 若用户要求底层 SQL 诊断，应切换到 `mysql-sql-analyzer`。

## 12. 失败场景与回退

- 范围内没有有效报告时，应明确说明缺失内容，不生成汇总文件。
- 遇到重复旧报告时，应排除并注明原因，而不是混入统计。
- 某些字段缺失时应写“未获取”，不能补造值。

## 13. 设计取舍

- 只汇总现有报告，速度快且风险低，但依赖上游单实例报告质量。
- 强模板输出保证一致性，但牺牲了部分自由表达。
