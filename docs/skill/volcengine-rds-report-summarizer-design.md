# Volcengine RDS 巡检报告汇总技能设计说明

## 概述

`volcengine-rds-report-summarizer` 负责对 **多个已有的单实例巡检 Markdown 报告** 做二次汇总，输出跨实例风险总览、共性问题和管理摘要。

它不负责重新采集数据，也不重跑单实例巡检脚本；它的输入必须是已有巡检报告，输出则是更适合管理者阅读的批量汇总结果。

## 架构

```text
用户："帮我汇总这个目录里的 RDS 巡检报告"
  → Agent 用 glob 枚举用户指定范围内的 .md
  → 校验哪些文件是 health-analyzer 生成的有效巡检报告
  → read_file 提取实例信息、评分、异常、行动建议
  → 先形成单报告摘要，再汇总跨实例共性问题
  → 按 summary_report_template.md 生成管理摘要 Markdown
```

## 设计要点

- **输入范围受控**：只处理用户明确指定目录或文件列表中的 `.md`，不默认扫描整个仓库。
- **只汇总不采集**：禁止调用云 API、数据库或 `volcengine-rds-health-analyzer` 的采集脚本。
- **有效性校验**：只纳入由单实例巡检 skill 生成、且章节结构明显匹配的 Markdown 报告。
- **先单篇后全局**：先抽取每份报告的关键信息，再做跨实例归纳，避免边读边下全局结论。
- **风险排序统一**：按风险等级、健康评分和高优先级异常数量排序实例，保证输出顺序稳定。
- **共性问题聚类**：重点归纳 CPU、内存、磁盘、复制延迟、QPS/TPS、IOPS 与网络等重复出现的问题模式。
- **模板强约束**：使用 `summary_report_template.md` 作为唯一骨架，不允许新增、删改或重排固定章节。
- **固定落盘命名**：保存路径固定为 `/memories/reports/皮氏咖啡线上MySQL巡检报告<YYYYMMDD>.md`，不因用户主题偏好而变更。

## 输出策略

- **聊天输出**：优先给出报告总数、纳入数、跳过数、风险分布、Top 风险实例和少量共性问题。
- **Markdown 输出**：默认采用正式巡检报告风格，保留 `封面信息`、`环境巡检说明`、`MySQL巡检分析`、`巡检汇总及问题建议`、`附录` 五段结构。
- **字段复用优先**：优先复用单实例报告中的 `health_rating`、`health_score`、容量和实例规格字段，避免二次猜测底层数据。
- **缺失值显式化**：无法判断的字段填“未获取”或“无”，而不是补造近似值。

## 目录结构

```text
backend/skills/volcengine-rds-report-summarizer/
├── SKILL.md                            # 报告筛选、提取、汇总和保存规则
└── assets/
    └── summary_report_template.md      # 跨实例汇总报告模板
```
