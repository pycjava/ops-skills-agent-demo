# 基础内置技能设计说明

## 1. 设计定位

`file_reader`、`shell_command` 和 `code_explainer` 构成项目中的基础能力层。它们不是针对某个业务域的复杂 Skill，而是为通用阅读、轻量检查和代码解释提供稳定的底层能力。

其中，`file_reader` 和 `code_explainer` 当前直接绑定给 `general` Agent；`shell_command` 作为基础只读能力保留在 Skill 目录中，便于后续按需装配。

## 2. 共同设计原则

这组三个 Skill 共享一些约束：

- **只读优先**：避免对本地环境或业务状态做修改。
- **小步操作**：先查看、再解释、最后总结。
- **证据化回答**：结论应来自实际读取的文件内容或命令输出。

## 3. `shell_command`

### 3.1 目标

`shell_command` 用于执行本地只读 shell 命令，适合：

- 查看目录结构。
- 查询文件内容或统计信息。
- 获取轻量系统状态。

### 3.2 允许的命令范围

Skill 将命令严格限制在只读集合中，例如：

- 文件与目录：`ls`、`cat`、`head`、`tail`
- 搜索统计：`grep`、`find`、`wc`
- 系统信息：`pwd`、`date`、`whoami`、`uname`
- 资源查看：`df`、`du`、`ps`
- 其他只读工具：`env`、`file`、`which`、`tree`

### 3.3 设计意图

它的存在不是为了替代通用 shell，而是为了给 Agent 一条“安全查看环境”的最低风险路径。

### 3.4 失败与边界

- 超时默认应控制在短时间内。
- 遇到交互式命令应改为非交互只读替代方案。
- 不适合运行安装、修改、删除或长耗时脚本。

## 4. `file_reader`

### 4.1 目标

`file_reader` 用于读取指定路径的文本文件内容，适合：

- 查看配置文件。
- 检查日志片段。
- 读取结构化文本、代码或 Markdown。

### 4.2 路径约束

该 Skill 强调路径规范：

- 优先使用相对于 `backend/` 的路径。
- 可复用 `glob` 返回的虚拟路径。
- 不使用 Windows 绝对路径、`~` 路径或越界路径。

### 4.3 设计意图

它让“读取文件”成为一个稳定语义动作，而不是让 Agent 随意拼 shell 命令去读文件。

### 4.4 边界

- 仅适合文本文件。
- 存在大小限制。
- 对超大文件应采用分段阅读或更合适的专用流程。

## 5. `code_explainer`

### 5.1 目标

`code_explainer` 用于解释代码片段，适合：

- 回答“这段代码在做什么”。
- 解释函数、类和模块关系。
- 识别关键逻辑、设计模式和潜在问题。

### 5.2 输出结构

该 Skill 倾向于按固定结构解释代码：

- 总体概述。
- 关键逻辑分段说明。
- 设计模式或实现技巧。
- 潜在问题与改进建议。

### 5.3 设计意图

它把“解释代码”从简单翻译提升为结构化教学输出，更适合在通用 Agent 中承担文档化和辅导职责。

## 6. 与 Agent Runtime 的关系

当前基础能力层与 Agent Runtime 的关系是：

- `general` 直接装配 `file_reader` 与 `code_explainer`，用于通用阅读与解释。
- `shell_command` 保持为独立的只读 Skill 定义，当前不在公开 Agent 默认白名单中。
- 这种拆分让基础只读能力既可复用，又不会默认扩大公开 Agent 的执行面。
- 它们的风险等级较低，适合作为默认基础能力。

从治理角度看，把基础 Skill 单独列出，也便于后续给其他 Agent 增配时做显式决策。

## 7. 典型使用顺序

```text
用户要求查看某文件
  -> file_reader 读取
  -> 如内容是代码，再用 code_explainer 解释

用户要求查看项目结构
  -> shell_command 查看
  -> 如需要进一步查看某文件，再切换到 file_reader
```

## 8. 设计取舍

- 将基础读能力拆成多个 Skill，语义更清晰，但需要 Agent 正确选择。
- 强调只读边界，安全性更好，但不适合承担自动修复或大规模分析任务。
