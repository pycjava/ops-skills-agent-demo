# Using-Superpowers 技能设计说明

## 概述

`using-superpowers` 是一个 **流程型元技能**。它本身不直接完成业务分析、排障或文档写作，而是负责约束 Agent 在任何任务开始前先判断“是否存在可用 skill”，并规定 skill 的调用顺序、优先级和执行纪律。

它的核心目标不是扩展具体领域能力，而是防止 Agent 在没有加载正确技能的情况下直接开始提问、探索代码或执行操作。

## 架构

```text
用户发起请求
  → Agent 先检查是否可能命中任一 skill
  → 只要存在命中可能，就先加载对应 skill
  → 先处理流程型 skill，再处理领域型 / 实现型 skill
  → 按 skill 自带清单和约束执行
  → 最后进入正常回答、分析或编码流程
```

## 设计要点

- **强制前置检查**：在澄清问题、读仓库、写计划或执行命令之前，先判断是否应加载 skill。
- **低阈值触发**：只要有 `1%` 的可能性适用，就应先调用相关 skill，而不是“先做一点再说”。
- **优先级清晰**：用户显式指令最高，其次是 `using-superpowers` 这类流程技能，最后才是默认系统行为。
- **流程图权威化**：`SKILL.md` 中的 DOT 决策图是权威规范，正文说明只能补充解释，不能覆盖流程。
- **反模式拦截**：通过 `Red Flags` 清单约束“先看一眼代码”“先收集上下文”这类常见绕过技能的行为。
- **多技能编排**：当多个 skill 同时适用时，先用流程技能决定方法，再进入领域技能落地执行。
- **平台适配**：针对非 Claude Code 环境，通过 `references/codex-tools.md` 做工具映射，保证技能可迁移。

## 适用场景

- 新会话刚开始，需要判断该走哪个专业 skill。
- 用户的请求同时涉及多个领域，需要先确定技能组合和执行顺序。
- Agent 容易陷入“直接探索仓库”或“先写再改”的惯性，需要统一前置约束。
